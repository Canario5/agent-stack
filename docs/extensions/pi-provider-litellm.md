## pi-provider-litellm
- **Install:** `pi install npm:pi-provider-litellm@x.x.x`
- **Purpose:** Registers LiteLLM proxy models in Pi and enriches them with metadata such as context size and pricing.
- **Login:** Use `/login litellm`, or `/login` → `Sign in with an API key` → `LiteLLM API key`. 
- **Backup fallback:** Manual auth editing should not normally be needed, but keep this short `auth.json` excerpt as a future fallback/backup reference:
```
"litellm": {
  "type": "oauth",
  "access": "redacted-token",
  "refresh": "",
  "expires": 253402300799000,
  "baseUrl": "https://litellm.redacted.com"
}
```
- **Note:** The `expires` field does not matter for static API keys.
- **Requirement:** The LiteLLM token must be allowed to call `/model/info` (for extra metadata); Pi can still list models without it, but `/model/info` is where LiteLLM exposes richer metadata such as context size and pricing. If `/model/info` is blocked, v2 falls back to `/v1/models`, then older `/health` discovery.
- **Usage:** Automatic. Open `/model` to refresh configured provider catalogs through Pi's native model lifecycle.
- **Provider aliases:** Optional. The backup `auth.json` snippet above is still valid for the default `litellm` login credential. Use `litellm.providers` in Pi `settings.json` only when you want multiple LiteLLM provider names, separate keys, or custom headers.
- **Optional features:** LiteLLM MCP tools and Skill Hub / Skills Gateway prompt injection are enabled by default. Disable them with `litellm.mcp.enabled: false` or `litellm.skills.enabled: false`.
- **Optional environment variables:** Usually none are needed if `/login litellm` works. Useful exceptions: set `LITELLM_API_KEY_HELPER` when your key expires and must be generated by a command; set `LITELLM_GCLOUD_TOKEN_AUTH=1` only if your proxy accepts Google ADC tokens; set `LITELLM_HEADERS` only if your proxy requires extra HTTP headers; set `LITELLM_OFFLINE=1` only to skip network discovery and use cached models; tune `LITELLM_DISCOVERY_TIMEOUT_MS` or `LITELLM_VERBOSE_DISCOVERY=1` only when troubleshooting discovery; set `LITELLM_MODELS_DEV=0` only if you do not want models.dev metadata enrichment.
